# PDF Document Accessibility & Screen Reader Verification Guide

This guide details how **CyberRakshak 1930** ensures that all generated legal and evidentiary PDF documents meet accessibility standards (WCAG 2.2 AA / PDF/UA compliance baseline), enabling blind and low-vision citizens to independently review their legal filings using assistive technology.

---

## 1. Generated Legal Document Types

The platform dynamically generates 5 core legal artifacts via `src/lib/pdfGenerator.ts`:

1. **Bank Freeze & Lien Request Notice (Section 91 BNSS 2023)**
   - *Target:* Bank Principal Nodal Officer / Fraud Desk.
   - *Purpose:* Immediate debit freeze and lien marking under Section 91 BNSS and RBI Customer Protection Direction.
2. **Cyber Crime Police Station FIR Complaint Dossier**
   - *Target:* Station House Officer (SHO) / Cyber Crime Police Station.
   - *Purpose:* Formal criminal complaint under BNS Sections 318(4), 319, and IT Act Sections 66C, 66D.
3. **Application under Section 503 BNSS for Release of Frozen Property**
   - *Target:* Judicial Magistrate First Class / Chief Judicial Magistrate Court.
   - *Purpose:* Formal court petition for release and refund of frozen illicit funds back to victim account.
4. **Digital Arrest Criminal Extortion FIR Complaint**
   - *Target:* Cyber Police & DoT Chakshu Unit.
   - *Purpose:* Criminal complaint for extortion (BNS 308), impersonation of public servant (BNS 204), and illegal virtual confinement.
5. **Section 63(4) BSA Electronic Evidence Authenticity Certificate**
   - *Target:* Judicial Magistrate / Court of Law / Cyber Forensic Registry.
   - *Purpose:* Tamper-evident cryptographic chain-of-custody and SHA-256 certificate for digital evidence.

## 2. Accessible Architecture & Structural Standards

### A. Document Metadata & Language Tagging
Every PDF generated by the application includes standard PDF Document Catalog dictionaries:
- **`doc.setLanguage(lang)`**: Emits `/Lang (en)`, `/Lang (hi)`, `/Lang (ta)`, etc. into the document catalog so screen readers automatically invoke the appropriate pronunciation synthesizer.
- **`doc.setProperties({...})`**: Sets `/Title`, `/Subject`, `/Author`, `/Keywords`, and `/Creator` metadata so assistive tools immediately announce document identity upon opening.

### B. Logical Top-to-Bottom Reading Order
All drawing and text stream operations follow a single-pass, strictly linear reading hierarchy:
1. **Header Banner:** Document Title & Statutory Act citation.
2. **Date, Case Identifier & Reference Number.**
3. **Recipient & Jurisdiction Addressing.**
4. **Subject Box & Applicable BNS/BNSS Sections.**
5. **Statement of Facts / Incident Narrative.**
6. **Forensic Evidence & Transaction Parameters (UTR, Accounts, IFSC).**
7. **Section 63 BSA SHA-256 Cryptographic Hash.**
8. **Statutory Relief Sought & Mandates (Prayer Points 1–3).**
9. **Complainant Signature & Contact Details.**
10. **Platform Identification & Generation Footer.**

### C. Clean Vector Text Stream
- All textual elements are rendered as real text operations (`BT ... ET`) rather than flattened bitmap/raster graphics.
- Paragraphs use `doc.splitTextToSize` with dynamic vertical tracking (`curY`) to ensure text never overlaps or streams out-of-order.

## 3. Screen Reader Verification Procedures

To verify that generated PDFs read coherently when modifying PDF templates in the future:

### Method 1: Automated Regression Test (Fastest)
Run the automated PDF accessibility and stream order suite:
```bash
npm run test:pdf-a11y
```
*Validates that all 5 PDF document types contain valid catalog language tags, complete metadata dictionaries, and sequential top-to-bottom reading stream tokens.*

---

### Method 2: NVDA (Windows)
1. Launch **NVDA** (`Ctrl + Alt + N`).
2. Open the downloaded PDF in **Google Chrome**, **Microsoft Edge**, or **Adobe Acrobat Reader**.
3. Use the following keystrokes:
   - `Down Arrow` / `Up Arrow`: Navigate line by line through the document.
   - `H`: Navigate between section headings.
   - `Insert + Down Arrow`: Read the entire document from top to bottom.
4. **Verification Checklist:**
   - [x] Document title is announced on open.
   - [x] Header is read first, followed by date, subject, statement of facts, and evidence table.
   - [x] Currency amounts (e.g. *Rs. 85,500*) and 12-digit UTR numbers are announced clearly.
   - [x] Complainant signature and footer appear at the end.

---

### Method 3: Apple VoiceOver (macOS / iOS)
1. Open the PDF in **Preview** or **Safari**.
2. Press `Cmd + F5` to turn on VoiceOver.
3. Use `Control + Option + Right Arrow` to advance sequentially through the text blocks.
4. Confirm that all structured metadata and evidentiary details are announced in top-to-bottom order.

---

### Method 4: Adobe Acrobat Reader "Read Out Loud"
1. Open the PDF in **Adobe Acrobat Reader**.
2. Navigate to **View > Read Out Loud > Activate Read Out Loud** (`Shift + Ctrl + Y`).
3. Press `Shift + Ctrl + E` (**Read This Page Only**) or `Shift + Ctrl + B` (**Read To End of Document**).
4. Confirm speech starts from the title banner and concludes with the signature block without skipping sections.
